# GManager v0.1 Scope (FINAL draft)
Windows-only, one game module (Plains of Pain), one server instance. Details: `ARCHITECTURE.md`. Nothing is created or deployed yet.
"UNVERIFIED" = depends on a PoP behaviour that must be confirmed on first install.

## In v0.1
1. **Single installer (no Docker/Pterodactyl)**
   - AC: one EXE/MSI on clean Windows 11 Home installs `gmanager.exe` as an auto-start service, with no other runtime required.
   - AC: it prompts for a backup folder and pre-suggests `P:\GManager\Backups` when P: exists.
   - AC: it creates the first admin account (email + password) and opens the dashboard at `http://127.0.0.1:<port>`.
   - AC: firewall rules for UDP 7777/27016 are added only after explicit consent. Uninstall removes the service and the rules, and keeps saves and backups unless the user chooses otherwise.
2. **Game-module core + PoP module**
   - AC: core services call only the module interface (install, launch args, stop strategy, config schema/validation, ready matcher, save paths, ports).
   - AC: PoP module installs via SteamCMD app 2227360 anonymously; launch args match §3 of the architecture doc; ready = `Set Game State: RUNNING`.
   - AC: unit tests run against a fake module to prove the core is game-agnostic.
3. **Installer/updater for the game server**
   - AC: "Install server" finishes with `PlainsOfPain.exe` present and SteamCMD output streamed to logs.
   - AC: "Update" runs stop → backup → `app_update 2227360 validate` → start. On failure the previous build still runs and the error is shown.
4. **Validating config editor (never overwrites manual edits)**
   - AC: form covers all known `server.json` keys. It rejects password >20 chars, `maxPlayers` outside **1–200**, difficulty outside 0–4/255, and `worldSize` outside {11,21,31,41,51}. It warns on non-default ports.
   - AC: after a manual edit to `server.json` (hash/mtime changed), the editor shows the change. Non-conflicting fields merge; conflicting fields prompt. The file is never silently overwritten.
   - AC: unknown keys survive a save. Writes are atomic with a `.bak`. A stale save gets `409`.
   - AC: the agent never rewrites config on server start.
5. **Backups & restore**
   - AC: manual and scheduled backups produce a timestamped zip (saves + config + SHA256 manifest) in the chosen folder. Retention prunes the oldest beyond N.
   - AC: restore requires `confirm=true`, stops the server first, and returns the world to the backup state (checked in-game).
   - UNVERIFIED: default save path and clean-stop method; until confirmed, backups use `userdir` when it is set.
6. **Crash & scheduled restarts**
   - AC: killing the process triggers a restart within 30 s. After 3 crashes in 10 min it halts and shows an error.
   - AC: scheduled restart fires at the configured local time and is logged. `ttr` interaction is tested and documented (UNVERIFIED).
7. **Status**
   - AC: dashboard and `gm-status` show Stopped/Starting/Running/Crashed/Updating. Running only after the ready line. Also shows uptime, PID, CPU/RAM and ports.
   - Player count: stretch, UNVERIFIED (query port).
8. **Log viewer**
   - AC: live tail within ~1 s over WebSocket; search/filter; cursor-paged history; rotated files downloadable; survives page reload.
9. **Dashboard auth (local accounts)**
   - AC: email + password login, Argon2id hashes, HttpOnly/SameSite cookies + CSRF, lockout after repeated failures.
   - AC: the agent refuses to bind anything except 127.0.0.1, and requests with a foreign Host/Origin are rejected.
   - AC: password reset works via local CLI. No email is sent.
10. **Network & CGNAT check**
    - AC: reports LAN IP, public IP (STUN/IP lookup) and router WAN IP (UPnP if available, else user-entered). It flags likely CGNAT/double NAT (100.64.0.0/10, private WAN, or WAN ≠ public).
    - AC: reachability shows "tested OK / failed / not tested". The external UDP prober is UNVERIFIED; manual test steps are shown when it is unavailable.
11. **PowerShell module**
    - AC: `gm-start/stop/restart/backup/status` call the API with a token. `gm-stop` requires `-Confirm`. No direct process access.
12. **Agent API contract**
    - AC: async `202` + `jobId`; `Idempotency-Key` replays the original job; `revision` + `If-Match` → `409`; cursor logs; `429` + `Retry-After`; `confirm=true` on stop/restore. All of it is documented.
13. **Releases & docs (unsigned)**
    - AC: CI publishes exe/installer + `SHA256SUMS`. A second CI build reproduces the agent exe hash (installer reproducibility UNVERIFIED).
    - AC: docs cover SmartScreen "Run anyway", `Get-FileHash` verification, Eero port forwarding (menu path re-checked before publishing), CGNAT next steps, and finding Steam admin IDs.
14. **Public site** (`gmanager.leotter.site`)
    - AC: static landing, docs and downloads (GitHub Releases links + checksums) and a Cash App donate link (`$leotterterry`). No accounts, no user data, no control features.
    - AC: deployed only after Terry's OK.
    - Stretch: client-side `server.json` builder that uses the same schema.
